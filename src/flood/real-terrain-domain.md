# 真实地形、模型适配与显示取舍

默认页面及 `?scene=dam-breach` 现在使用西藏林芝附近的 **Cesium World Terrain**。`?scene=tibet-breach` 也进入该场景；`?scene=synthetic-breach` 保留合成山谷作原理对照。

点击“开始溃坝”播放，或逐次“推进 10 秒”。“查看坝口”从下游观察缺口和跌水，“查看全域”观察传播范围。“收起控制”方便窄窗口查看场景。页面上游在北侧，下游向南；显示与计算使用同一个真实地形 provider。

## 真实数据和假设设置

| 项目 | 本次使用的数据 |
| --- | --- |
| 地形 | `createWorldTerrainAsync({ requestVertexNormals: true })`，通过 `sampleTerrainMostDetailed` 采样最详细可用层级 |
| 区域 | 西南角 94.323°E、29.686°N，向东 3000 m、向北 2880 m，林芝附近河谷 |
| 网格 | 100 × 96，30 m 单元，共 9600 个；固定 ENU 计算床面 |
| 高程 | 在线采样约 2965.34–3494.16 m，未压平、挖槽或添加人为下游坡度 |
| 底图 | Cesium 世界影像；只用于显示，不作为高程输入 |
| 坝段与库水 | 横谷假设坝段，北侧预置等水位蓄水，初始约 8,795,231 m³；不是一个已校准真实水库 |
| 缺口 | 30 s 开始，60 s 形成，最终宽 72 m；最低底高程受原始地面约束 |
| 边界 | 南侧仅排水，其他三侧封闭；不计算域外水位和回流 |

先进行了较宽范围的真实地形采样，检查低地位置和南北高程趋势，再选择以上计算区。地形只在准备计算域时采样一次，相机的地形 LOD 不改变推演地面。30 m 是本次浏览器负担与范围的折中，不能还原小沟渠、细窄河槽和坝口内部三维结构。

Cesium 官方接口提供的采样高程按 WGS84 椭球高处理，再通过 ECEF 转成本地 ENU z；不能直接把国家高程或别的垂直基准填入数组。参考 [Cesium Terrain 与采样 API](https://cesium.com/learn/cesiumjs/ref-doc/global.html#sampleTerrainMostDetailed)。本次选用了仓库已有凭据可用的 Cesium provider。天地图需要相应 TerrainProvider 适配与凭据；本次没有实现或验证天地图 provider。

## 水从哪里越过坝

实际出流方向取决于两侧水面高程，屏幕的上下还取决于相机。这个预设把北侧作为上游，向南下泄；坝口近景从下游观察，上游库水位于后方。

本次模拟的是预设缺口逐渐拓宽、降低的过程。水面高于当前缺口堰顶时越流；缺口较浅时从上部越过，继续下切后出流位置随堰顶降低。它不是预设一个坝底孔洞，也没有挖穿真实地形。

以前只连接上、下游单元中心的水面。下游水位很低时，这条插值面可能穿过仍存在的坝体。现在水面三角形只有在高于有效墙顶时才允许跨墙；需要跌落的部分单独绘制：

```text
上游水面 → 当前缺口堰顶上方的水片 → 下游坝面之外的跌水 → 下游水面
```

`sampleWallOverfalls` 读取成果水深、已知流速、墙顶和当前溃口，计算显示用的水片位置。水片出口高于有效堰顶，落点是下游水面，不增加或扣减求解器水量。没有流速的外部成果不凭空生成有方向的跌水动画；分析图层不显示跌水。

这里采用薄水片和程序纹理表达越流、跌落和底部泡沫；临界水深位置使用简化堰流关系。它不是三维流体、粒子飞溅、真实体积水或经过校准的堰流几何。这样能改善水从哪里流出的可读性，也保持渲染层与水量计算分离。

## 统一什么，而不是统一文件格式

统一的是**求解器看到的物理输入**。Cesium 地形、其他 TerrainProvider、GeoJSON 轮廓、3D Tiles 建筑或人工挡墙，先通过各自适配器转换到同一 ENU 网格。

```text
TerrainProvider / DEM ───→ 基础地面网格 ──┐
模型轮廓 + 顶高程 ──────→ 实心柱状障碍 ───┤
挡墙线 + 墙顶高程 ──────→ 网格面障碍 ─────┤→ composeFloodDomain → 同一求解器
桥梁 / 架空结构 ────────→ 排除桥面，保留通水空间；桥墩另设实心轮廓

外部水动力成果 ─────────→ FloodDataset → 同一回放、分析和渲染图层
```

| 对象 | 已实现的规则 | 取舍 |
| --- | --- | --- |
| 裸地形 | 采样为固定床面 | 准备时网络请求；不依赖相机 LOD |
| 实心模型 | 简单平面轮廓内，单元中心床面抬到 `max(地面, 模型顶高程)` | 将建筑视作实心竖直柱，屋顶以上可积水；不处理室内、挑檐、穿楼和模型内通道 |
| 薄挡墙 / 堤坝 | 墙线与相邻单元中心连接线相交时，将对应网格面设为墙顶 | 低于或等于墙顶阻断，高于后堰流；两方向都支持，但每个面使用一个墙顶标量 |
| 桥梁 | 桥面不作为实心柱输入，桥墩可以单独提供实心轮廓 | 保留桥下通路；暂不处理桥底压流、涵洞公式和自动识别桥洞 |
| 3D Tiles | 适配器输出上述轮廓、墙线和 ENU 高程 | 尚无任意瓦片的自动几何解码与角色识别；不能用视角拾取到的模型最高点统称为地面 |

这是一种 2.5D 计算域：每个单元有一个有效床面，每个网格面可有一个墙顶。一个 x/y 上多层可通水空间、地下管道、桥底承压过流等，需要以后独立的连接或结构模型。显式角色能避免自动把桥面变成横跨河道的实体坝。

## 适配 API

`FloodObstacle` 支持 `solid` 和 `wall`。坐标为局部 ENU `[east, north]` 米，顶高程为绝对 ENU z 米。实心轮廓应为简单、无自交且无孔的多边形；有孔模型应由适配器拆分。墙线可以是折线。细于单元的实心轮廓可能不包含任何单元中心，薄障碍应优先表示为墙线。

```ts
import { composeFloodDomain, createFloodSimulation, type FloodObstacle, type FloodGrid } from './flood/core'
import { sampleTerrainGrid, createCesiumFloodLayer } from './flood/cesium'

// viewer、TerrainProvider 与 3D Tiles 图层由宿主拥有。
const layout: FloodGrid = { columns: 100, rows: 96, cellSize: 30, origin: [94.323, 29.686, 0], elevation: [] }
const ground = await sampleTerrainGrid(viewer.terrainProvider, layout)
const base = Math.min(...ground.elevation)
const obstacles: FloodObstacle[] = [
  { id: 'building', kind: 'solid', footprint: [[100,100], [160,100], [160,160], [100,160]], topElevation: base + 15 },
  { id: 'wall', kind: 'wall', path: [[0,600], [1200,600]], crestElevation: base + 5 },
]
// 示例坐标与高程仅展示接口；实际应由源模型坐标转换和角色判定获得。
const domain = composeFloodDomain(ground, obstacles)
const simulation = createFloodSimulation({ ...domain, outlet: 'south', inflow: { discharge: 350, until: 240 } })
const layer = createCesiumFloodLayer({ viewer, ...domain, showGround: false })
layer.update(simulation.advance(10))
```

`composeFloodDomain` 不修改传入地形或已有挡墙；重叠实心障碍取最高床面，重叠墙线取最高墙顶。初始库水应在组合后的计算域上计算，避免先灌水再把建筑挤入水中。返回网格中的 `elevation` 是**有效计算床面**，可包含实心模型顶部；原始地面由宿主另行保存。外部成果转换器也须明确床面含义，不能混用地面和屋顶水深。

`outlet: 'north' | 'south'` 控制开放下游，默认 north。复用者必须按自己的真实区域选择出口，不能依赖默认的“南高北低”。页面“Cesium 地形与泄洪点”可切换出口；切换会重置推演。成果 JSON 保存床面、水深、流速与可选坝段/缺口，但仍不是完整工况重启文件，出口和入流等运行配置应由宿主保存。

## 本次实际验证

通过公开 `sampleTerrainGrid` 对在线 Cesium World Terrain 采样，再调用公开 `createFloodSimulation`，完成 1800 s 推演，保存 181 帧成果并分析，未修改原始高程。

| 时刻 | 过坝出流（向南） | 南侧 55% 区域淹没（≥2 cm） | 域外排水 |
| --- | ---: | ---: | ---: |
| 30 s | 0 | 0 | 0 |
| 60 s | 499.10 m³/s | 0 | 0 |
| 90 s | 3073.86 m³/s | 0 | 0 |
| 300 s | 3649.82 m³/s | 16.38 ha | 0 |
| 900 s | 2610.68 m³/s | 100.89 ha | 0 |
| 1800 s | 1832.38 m³/s | 183.87 ha | 878,150.85 m³ |

1800 s 时域内存水约 7,917,080.27 m³，初始水量约 8,795,231.12 m³，平衡误差约 -3.73e-9 m³。0.1 m 阈值下的曾淹没面积约 327.06 ha，最大采样时刻面积约 317.79 ha，最大水深约 12.49 m。库水可能触及计算域边界，范围与初始体积只描述这个假设工况。

41 项洪水模块测试包含南北出口镜像守恒、模型轮廓、两方向墙线、越顶水片方向与堰顶高度，以及之前的地形、溃坝和淹没统计。严格类型检查范围为洪水模块，整个旧 demo 的既有类型问题未纳入本次修改。真实地形与采样、假设水动力和视觉示意是三个不同层次，水量守恒与画面显示都不能代替工程精度校准。

浏览器也连续播放到 1800 s，真实影像与原生地形保持显示。域内水量约 7,917,080 m³、下游排出约 878,151 m³、南侧 55% 区域淹没约 183.87 ha，与离线 API 推演一致；该次浏览器平衡误差约 1.86e-9 m³。坝口 60 s 近景确认越流水片位于有效坝顶以上，随后在下游面外跌落。最大水深、首次到达和累计淹没时间图层切换成功，未发现新的 shader 错误。生产构建通过，纯 core 独立打包仅包含九个本地计算文件，无 Vue / Cesium 运行依赖。
