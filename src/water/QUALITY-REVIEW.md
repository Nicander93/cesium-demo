# 水面质量评审与下一项实验

日期：2026-10-14。当前代码基线：`802a62f`，Cesium 1.132.0。

目标调整：先建立可信的水面光学与近远景效果，再继续持续泄洪推演。此前 API、编译、冻结像素和交互测试证明的是可调性与稳定性，不能证明新效果优于原始 `/water` 页面。

## 代码中已确认的问题

- `src/water/material.ts:178` 起已经自行计算光照、高光、菲涅耳与倒影，并在第 203 行合成到 `material.diffuse`。
- `src/water/surface.ts:84` 创建的 MaterialAppearance 没有设置 `flat`；Cesium 1.132 默认值为 false。
- 安装版本的 `TexturedMaterialAppearanceFS.glsl` 在非 FLAT 路径调用 `czm_phong`，后者会再次对 diffuse 做环境/漫反射处理。结果是已经合成的倒影也经过该光照路径。
- 水面计算的自定义法线没有赋给 `material.normal`，Cesium 后续光照仍采用默认材质法线。这个路径在 legacy 和 multiscale 中都存在，不能单凭它断言新版本变差的全部原因；其与两种模式的光照方向、反射权重共同产生的视觉贡献需要同场景 A/B 实验量化。
- 水体颜色目前是表面着色加简单 Alpha 混合，没有按水下场景颜色、深度和光程实现折射、吸收与散射。
- 几何为静态水面，波纹改变法线和颜色，没有波峰位移。远景过滤细波后，也没有完整地保留被过滤波纹的统计粗糙度/高光响应。
- 原始页 F0 为 0.3，真实页面预设为 0.045；视角、光照和反射开关也不同。不能直接用不同页面截图证明一种算法更先进。
- `edgeFadeWidth` 按通用 UV 渐隐，并不等价于真实岸线距离或人为裁剪边距离。它不应被当作完整的接水线方案。

## UE 文档与社区实践给出的方向

Epic 的 [Single Layer Water 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/single-layer-water-shading-model-in-unreal-engine) 将水面反射与水体吸收、散射、折射一起处理，并利用已渲染的场景颜色和深度进行合成。可借鉴其职责划分；不能把 UE 的延迟渲染 Pass 直接移植为 Cesium Material，也不能把普通 Alpha 混合称为同等实现。

Epic 的 [水面网格与材质文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/water-meshing-system-and-surface-rendering-in-unreal-engine) 描述相机相关网格 LOD、远端简化材质及共用基础材质的水体实例。对本项目的启示是共享底座、按视距和像素足迹调整细节，而不是要求所有距离使用完全相同的显示细节。海洋远端网格的做法不能直接用于填补有限湖泊的错误裁剪。

Epic 的 [Water Body 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/water-body-actors-in-unreal-engine) 区分同高程湖泊与可变高程、带速度信息的河道。湖泊与水库多数差异可以由参数表达；河道、动态洪水还需要额外输入与算法分支。

社区 [UE4.26 海洋远景讨论](https://forums.unrealengine.com/t/ue-4-26-ocean-distance-rendering/475516) 包含作者的地平线问题和远端材质建议；版本较旧，只作为问题案例。[Epic 社区 Arch Viz 教程](https://dev.epicgames.com/community/learning/tutorials/nwML/unreal-engine-capturing-reality-the-epic-games-ecosystem-for-arch-viz-part-1) 的水体部分比较了不同 UV 尺度的视觉表现。该示例使用 Twinmotion 玻璃材质模拟小水体，不应视为可直接移植的 Cesium 高质量水面算法。

## 对近远景参数的决定

采用“一套水体属性 + 连续自适应显示策略”。吸收/散射、风浪和流场参数描述水体，不能随相机任意改变物理含义。渲染器根据距离、投影像素尺寸和观看角度调整采样与表现：

| 范围 | 重点 | 应避免 |
| --- | --- | --- |
| 近景 | 可分辨的细法线、倒影扰动、接水线和可用深度下的透水表现 | 密集等幅噪声、大片无来源泡沫、将倒影再当漫反射处理 |
| 中景 | 主波尺度、流动方向、环境倒影和水体形状 | 各分量同时强化而形成花纹毯 |
| 远景 | 稳定的环境反射、整体明暗和轮廓；未解析细波转为统计粗糙度响应 | 细纹闪烁、硬切 LOD、细纹消失后只剩纯色多边形 |

物理颜色和边界保持一致，质量/LOD 分支连续过渡。当前 fwidth 过滤只是其中一个环节。有效的距离阈值和性能预算必须通过实际相机与显示分辨率测量，不先拍定三个硬编码距离。

## 四组标准案例

| 案例 | 主要辨识特征 | 参数与输入 |
| --- | --- | --- |
| 湖面 | 平静时可读的倒影、微风细波、自然接水线 | 风浪、粗糙度、水体光学参数；平面水位与岸线 |
| 水库 | 大面积水体、长尺度风浪、岸坡/坝体倒影、水位变化 | 与湖面共享主体，采用不同尺度和浑浊度；岸坡/坝体及水位 |
| 河道 | 明确的下游流动、转弯与快慢流变化、局部泡沫 | 光学底座 + 速度/水深或显式流图；可变水面与岸线 |
| 洪水面 | 浑浊、湿干前沿、局部冲击及不断变化的范围 | 光学底座 + 时序水深/速度、动态边界与局部泡沫来源 |

预设保存参数和能力选择，不复制四套 Shader。湖泊不能通过“动画速度加大”冒充真实河流，静态平面也不能通过颜色预设冒充洪水演进。公共 API 保持简单，渲染分支与兼容检测留在内部；暂不确定插件或包结构。

## 首个值得实施的实验

先仅验证一个静水案例的光学底座，使用原始 `/water` 场景或同等可控、带倒影参照物的场景。两条路径共用水域、法线贴图、光照、观看角度、视觉时间、反射开关和分辨率预算。

1. 原始路径作为视觉基线；保留它，直到替代方案通过视觉验收。
2. 波纹先保持相同，独立比较现有通用材质光照与只计算一次的水面光照合成；核实线性颜色与输出、法线空间和反射权重。不要同时更改波浪数量与配色。
3. 分项对比倒影、水体色、高光、法线和岸线；先让整体像水，再添加细节。
4. 成立后再加入深度输入实验。Cesium 的后处理颜色/深度可能已经包含水面，必须验证如何获取水面之前的场景，避免自采样反馈；缺少深度时不伪造真实水深。
5. 建立近/中/远、低角度/俯视的固定镜头，保存原始与候选的截图和连续移动录像。候选至少保持原始 Demo 的水体辨识度、倒影可读性和自然颜色。

第一轮结束判据：同条件视觉认可，未出现新增接缝/闪烁，连续相机移动可用，反射资源可释放，记录加载稳定后的性能。测试/GPU 编译仍要通过，但不替代视觉判断。随后扩展湖面、水库、河道和洪水面预设；持续泄洪工作在静水底座达标后恢复。
