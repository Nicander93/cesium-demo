# 3D Tiles 如何参与洪水计算

状态：真实 3D Tiles 的计算域提取仍为设计，尚未实现或验收。当前已接入 Cesium TerrainProvider 采样、网格面挡墙漫顶、局部惯性模型和外部成果回放；挡墙为手动生成的示例，尚未实现从 3D Tiles 自动提取墙顶，也未支持建筑绕流或桥下过水。

目标是把 3D Tiles 中与水流有关的信息转换成可检查的水力计算域。模型仍由 Cesium 加载和显示；求解器读取经过处理的地面、障碍和过水结构，而不在每个时间步直接遍历渲染三角形。

## 同一个模型可能有不同的计算角色

| 模型内容 | 转换后的计算输入 | 水流应发生的变化 |
| --- | --- | --- |
| 地面、山谷、河岸、河床 | 地面高程、有效区域 | 影响水面坡度、储水和传播路径 |
| 封闭建筑、实体挡墙 | 建筑占地范围、封闭单元或单元边界 | 流量不能穿过封闭实体，应沿道路和空隙绕行 |
| 堤防、坝体、路堤 | 单元边界上的堤顶高程及连接规则 | 水位低于堤顶时挡水；漫顶时采用相应通量或结构关系 |
| 桥梁、涵洞、闸门 | 桥下通道、断面、底高程、净空及过水关系 | 允许桥下或涵洞过水，必要时限制流量 |
| 树木、开放围栏、装饰物 | 按需忽略，或转换为阻力/开口率 | 不应一律按屋顶式实体挡水 |
| 任意场景中的外部模型回放 | 位置、深度遮挡、模型展示 | 保持输入成果；不自动重算或改变洪水传播 |

3D Tiles 是空间数据的组织和传输格式，不保证附带建筑、桥梁、河床等水力语义。BIM、CityGML 等源数据如果保留了分类和属性，优先使用这些信息。倾斜摄影中的建筑、地面和树木常混在一个网格里，需要区域分类、辅助矢量或人工修正。

## 地面采样可以作为入口，不能承担全部语义识别

Cesium `Scene.sampleHeightMostDetailed` 支持异步采样场景中 3D Tiles 的最高细节层级，并允许排除对象。它返回几何高度，不能判断命中的是屋顶、桥面、树冠还是河床。`sampleTerrainMostDetailed` 查询 terrainProvider，也不能自动把独立的 3D Tiles 模型变成计算地形。

建议的采样流程：

1. 用户指定计算区域、目标网格尺寸，以及参与计算的 tileset 和角色；避免全场景无差别采样。
2. 先记录 tileset 的位置变换、版本和目标网格。所有采样统一到 WGS84 椭球高，再转换成同一局部 ENU；使用最终显示位置，而不是忽略 `modelMatrix` 的原始模型坐标。
3. 暂停推演；排除水面网格、合成地形、辅助标记以及不参与计算的对象，防止采到自身或显示用覆盖物。
4. 分批进行最详细层级的异步采样，支持进度、取消、超时及失败标记。不能依赖当前视角下的 LOD 或屏幕截图作为稳定计算输入。
5. 转换采样结果并显示高程、缺失位置和障碍预览。无法取到高度的地方保留为未知；只有用户选择了合适的备用 DEM 时才回填，不能静默使用 0。
6. 结合源语义、建筑足迹或用户标注区分屋顶、桥面与地面。公开高度采样接口不会自动返回完整的多层垂向结构。
7. 用户可修正地面、建筑边界、堤顶和桥下通道，确认后冻结计算域并缓存。模型位置、参与角色、网格或修正改变时使缓存失效；相机移动不会改变已经冻结的计算域。

仅使用最高表面高度作为一种可选择的 DSM 近似是可行的，但需要明确标签并展示检查结果。它会错误处理桥下空间、树冠、架空建筑和未被观测到的河床，不能直接宣称完整模型参与水动力计算。

## 计算输入和成果输出保持独立

建议在后续引入独立的 `HydraulicDomain`。以下字段是设计提案，不是当前 v1 JSON 已支持的字段：

- `groundElevation`：地面高程，局部 ENU 上方向坐标。
- `valid`：是否有可信的地面与计算区域信息。
- `solid`：封闭实体占用的计算单元；在这种简化假设下，不储存水且所有相关边界无通量。
- `roughness`：单元 Manning 摩阻系数。
- `eastBarrierCrest` / `northBarrierCrest`：单元边界的堤顶或挡墙顶部高程，无障碍时为空。需要与通量数组的方向、尺寸一致。
- `structures`：桥涵、闸门等过水连接，需要专门的几何和水力关系；不是只有一个布尔开关。
- `provenance`：源模型、最终变换、采样策略、源高程基准、修正和缺失情况，用于重建与验收。

当前 `FloodGrid.active` 表示有效数据区域，主要用于外部成果的几何显示。它不能改名或直接解释成实体建筑，更不能只隐藏渲染三角形就宣称水已经绕流。内置求解器还需要实现相应的边界通量和储水处理。

小于当前 12 m 网格的墙体或河道，可能在单元中心采样中被完全漏掉。优先用矢量边界/断裂线约束单元边界，或局部提高分辨率。粗网格中一个单元部分被建筑占据时，需要进一步考虑有效储水面积和边界开口率；第一轮可明确只接受对齐网格的封闭实体近似。

保持以下两条路径：

```text
3D Tiles + DEM + 语义/人工修正 → HydraulicDomain → 内置求解器 → FloodDataset → 渲染
外部模型成果 → 成果适配器 ────────────────────────→ FloodDataset → 渲染
```

外部成果播放时，优先保留模型计算时使用的地面与坐标信息。若场景模型和成果高程不一致，应提示错位及来源，让用户修正转换或场景配准；不要静默覆盖外部结果的地面或水深。后续如支持“用当前场景重新计算”，必须明确进入新的推演场景。

## 接下来的实现与验收顺序

1. **先验证障碍会影响计算**：在合成山谷增加封闭建筑和挡墙，求解器实现对应无通量边界。对比有无障碍的水深、流向和下游到达过程，验证不是只遮住水面。
2. **接入地面类 3D Tiles**：从限定区域提取、修正并冻结地形，在同一网格上对比已知地面，检查高程与坐标一致性。
3. **接入建筑足迹与实体障碍**：模型用于定位和展示，足迹来自源语义、辅助矢量或可编辑标注。窄墙用单元边界表示。
4. **增加堤坝漫顶**：验证水位低于堤顶时不会漏水，超过阈值后按照定义的过流方式进入下游，并检查水量守恒。
5. **单独实现桥涵连接**：模型视觉结构与水力结构对应。桥下正常过水、桥墩绕流和漫顶分别验证；目前的单层高度网格不能完整表示桥下与桥上两层水流。

必要的验收案例：封闭建筑无穿透、绕流后守恒；同一障碍在不同视角下产生相同计算结果；采样失败不静默变成低洼坑；平移或旋转模型后缓存失效并重新配准；桥面不被误当作堤坝；仅用外部成果回放时结果不被场景模型改写。
