# 城市渲染推进与验收

## 工作顺序

每轮先固定参考画面和视角，再确认代码成因，按独立模块修改，最后分别记录类型/构建检查与浏览器画面证据。模型光照、云、水、雨逐项验收，避免同时改变曝光、材质和天气后无法判断来源。

## 本轮：晴天云与水波

| 项目                 | 原因与修改                                                                    | 对照方法                                                       |
| -------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 晴天云底偏黑         | 接入地面反弹光，恢复天空补光，降低晴天层密度与厚度；使云亮度参数实际生效      | 晴天→河岸看云，固定 14:00、25% 云量、900m 厚度，再只改变云亮度 |
| 晴雨天外观接近       | 晴天与雨天分别设置光学密度和层厚度                                            | 同一视角切换预设；晴天有蓝天间隙，雨天更厚更暗                 |
| 水面只有细纹理       | 在细法线纹理之外增加 14m、7m、3.2m 行进波的解析法线；主波占优以减轻规则棋盘纹 | 河岸视角固定相机，分别设波浪强度 0 和 1.2                      |
| 速度修改造成相位跳变 | WaterSurface 积累动画时间，修改速度时先结算旧速度对应的时间                   | 速度 1→0→1：暂停和恢复；风速变化调整幅度和速率                 |

晴天默认 14:00、云量 25%、下层厚度 900m、云亮度 1.85；雨天为 15:00、云量 83%、厚度 1700m、云亮度 0.95。低画质关闭额外地面反弹光采样以控制开销。

水面这轮改动为法线起伏、光照与倒影扰动，底层反射几何仍是平面；未实现几何浪峰、岸边拍浪、折射水底或流体模拟，不能把这轮描述为完成真实水体渲染。

## 资料与取舍

- [three-geospatial 官方云源码](https://github.com/takram-design-engineering/three-geospatial/blob/main/packages/clouds/src/shaders/clouds.frag)：太阳/天空散射与近似地面反弹光。沿用现有 MIT 适配模块，没有更换引擎。
- [GPU Gems 第 1 章](https://developer.nvidia.com/gpugems/gpugems/part-i-natural-effects/chapter-1-effective-water-simulation-physical-models)：用不同尺度的周期波构成水面，区分较长起伏和细节法线。当前只落实法线与运动，不宣称几何位移已完成。
- [Three.js Water 官方文档](https://threejs.org/docs/pages/Water.html)：平面反射、法线纹理、太阳方向、时间和倒影扰动是可独立调节的环节。

## 后续优先级

1. 在同一视角完成晴天/雨天与水波暂停/恢复的浏览器对照，记录截图与错误日志；连续拖动需要另外验收，截图不能证明逐帧无闪烁。
2. 若云仍像背景，单独检查层内视差、球壳映射与采样稳定性，先排除接入错误再考虑重建云形。
3. 若水仍缺乏真实感，再评估细分网格位移、岸边过渡与折射；保留当前共享水面接口。
4. 最后统一模型阴影和环境光，再推进雨滴撞击与积水。已看到 B 站参考画面；后续按云团体块、垂直发展和光照层次对照，不能从画面推断作者源码。


## 本轮实际验收记录

应用内浏览器已成功打开城市页，街区 65/65、云管线均就绪。实际检查晴天河岸、云亮度调节、水波暂停和恢复、雨天预设，以及一次河岸视角拖动；控制台没有渲染错误，存在 texture3D.flipY 不支持的警告。截图保存在本聊天的可视化输出目录，分别为 city-fair-clouds-river-20261013.jpg 和 city-rain-clouds-river-20261013.jpg。该窗口显示约 50–60 FPS，只是本次运行观察，不作为用户设备性能基准。

现场发现模型接收自阴影时出现随视角变化的斜条纹，关闭后消失；城市默认暂时关闭“模型自阴影（实验）”，继续保留建筑向地面的投影。这是暂时限制接收阴影的范围，尚未解决阴影 bias/级联精度问题；下一轮需单独校准，不能宣称自阴影已修复。Three 对照的自阴影默认配置保留。

代码检查：城市类型检查通过，城市与共享水面共 34 项回归检查通过；新增检查覆盖变速相位连续、暂停/恢复和无效参数拒绝。实际拖动后的截图正常，但这不能证明拖动全过程逐帧无闪烁。


浏览器帧对照：关闭倒影和车流、固定相机后，对同一水面区域比较两帧 RGB 差值。波浪暂停时平均差值为 0，恢复运行后为 3.8603（0–255 标度），证据见聊天输出目录的 river-motion-check.json 和对应四张截图。这证明当前水波确实在运动，不是测量真实水体物理特性。生产构建与 diff 格式检查通过。

### B 站画面对照

本轮后段浏览器成功打开 [Cesium体积云的阶段性成果](https://www.bilibili.com/video/BV1j6gWzzE8F/)，看到傍晚暖色逆光和约 01:02 的白天云团画面。相比当前示例，参考画面的云团体块和垂直发展更完整，亮边与云底阴影分布更清楚。这里是从画面观察出的差距，没有取得作者源码，也不能据此确认算法。

下一轮云形验收：固定相机和太阳，先比较下层积云的轮廓与不透明程度，再只改变层厚度/侵蚀程度，检查近景侧面、云内穿行和高空俯视。阶段目标是有体块的积云，保留自然灰色云底，不把全画面曝光当作云形修正。暂不同时修改水面、阴影或模型 IBL。
