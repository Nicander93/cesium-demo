# 云原始输出审查（2026-10-26）

用户明确拒绝了前一轮截图。本记录不把构建、数值检查或帧率当作视觉验收。

## 前一轮为什么没有达到目标

本地社区路径没有复现参考的核心云密度和照明模型，只借用了低分辨率、分级重建和预备照明等思路。参考代码的存在不能证明当前模型可调到相同观感。前轮未先分离原始云输出与重建输出，过早把大量颗粒交给时序平均处理，这是推进和验收方法的问题。

## 固定对照方法

- 同一 1600×900 场景、400×225 主云、800×450 resolve，balanced、晴天、coverage=0.32、完整云场。
- 三个固定姿态：云海默认、4500m 仰视、4500m 向下俯视。它们用于重现截图中的问题类型，不是从用户浏览器恢复的精确姿态。当前嵌入浏览器控制工具初始化失败，测试使用独立 Chrome / RTX 5070。
- 读取真实主云 MRT、速度、resolve 和 GL uniforms，区分原始输出、重建和相机问题。仰视时原始 alpha 为零，静止速度 P95 约 0.000055 像素，不支持先改相机/静止矩阵的假设。
- 实验只在独立测试浏览器拦截 shader 或 uniform；没有把这些测试拦截器放进运行代码。完整结果在 test-results/cloud-sampling-audit-20261026/isolation.json。

## 已确认的因果

1. 原始云图就有强烈明暗颗粒。关闭近光估算，俯视的原始不透明区域高频残差约降低 85%，但体积光影也明显变平，因而拒绝直接关闭。
2. 固定中点显著降低颗粒，却产生硬切片和台阶；恢复原二次光深细分也未单独解决问题，均未采用。
3. 原最小 80m 单元与均匀剩余预算会越过近处云表面。缩小近处单元，并把同一预算优先用于近处，改善了原始输出，也消除了固定机位中的孤立远云细线。末单元仍覆盖全部剩余距离；没有裁去远云或缩短云场。
4. 固定 160m 的单点近光估算在浓云中可能跨越多个平均自由程，使随机首样本位置变成强烈明暗跳变。将该短段限制为 min(160m, 1/extinction)，让当前可见介质的消光尺度参与估算；余段仍交给 BSM。
5. 整体降低光学密度会把云变薄、扩大透地面区域，未采用，不能把这项假设写成已经成立的根因。

## 本轮仅采用的改动

- provider-settings.ts：最小近处步长改为 20m；总步数仍为 96 / 128。
- clouds.frag：剩余步长预算改为近处优先；近光段按消光尺度约束。

没有改天气覆盖、云形函数、云层高度、曝光、分辨率、时序重建或 BSM 结构。较小积分单元使纹理过滤足迹更细，所以会显露原来被过度过滤的云体细节。这是采样行为变化，不是新的形状纹理。

## 验证和边界

| 固定姿态 | 原始高频残差：之前 → 当前 | 重建高频残差：之前 → 当前 |
| --- | --- | --- |
| 默认云海 | 0.02384 → 0.01046 | 0.00496 → 0.00343 |
| 向下俯视 | 0.07764 → 0.02049 | 0.00778 → 0.00244 |

指标是在 alpha>0.99 的区域计算亮度相对四邻域平均值的 RMS，也包含真实高频纹理；它帮助定位差异，不等于纯噪声测量或视觉评分。数据来自固定机位截图附近的单帧，不能代替长时间统计。

- 当前项目代码的实际 framebuffer 输出与实验版本一致，有限、无 GL 错误。
- 鼠标、CDP 模拟触摸均实际移动相机，分别保存按下移动、释放后 100ms、稳定后截图；云场始终开启。
- 5174 开发页面五组交互的 P95 RAF 间隔为 7.2–14ms，测量中无 >50ms 间隔；4K 是浏览器视口，实际缓冲仍为 1600×900。独立 Chrome 的结果不能等同于用户当前嵌入浏览器或真实触屏体验。
- 69 项单测、类型检查和正式构建通过。本轮没有重新证明冷启动预算。
- 运行截图仍有颗粒、云边偏软和远处层带；当前模型与参考核心密度/照明仍未对齐，视觉验收未通过。不能把本次局部采样修复表述为已完成真实感目标。
